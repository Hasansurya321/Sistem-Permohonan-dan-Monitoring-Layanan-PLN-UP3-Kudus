# Forgot Password Revision Agent

This custom agent is designed for the PLN-Monitoring repository when the task is to revise the Forgot Password implementation according to the final stabilized multi-guard auth architecture.

## What it does

- Enforces strict separation between customer (`web`) and employee (`employee`) password reset flows.
- Avoids default Laravel hybrid auth and default password reset broker patterns.
- Uses separate token tables and reset lifecycle logic.
- Keeps existing activation/admin approval flows untouched.
- Adds and validates automated tests for customer and employee reset flows.
- Maintains current auth UI styling and animation.

## When to pick it

Use this agent instead of the default agent when the task involves:

- updating password reset logic in this repository
- ensuring multi-guard auth consistency
- preserving custom token lifecycle architecture
- adding or revising tests for reset flows

## Example prompts

- "Implement customer forgot password flow with custom customer_password_reset_tokens and explicit Auth::guard('web')."
- "Separate employee reset routes and controllers from the customer reset flow and add guard-specific validation."
- "Create tests that block pending customer reset requests and reject wrong-guard reset tokens."
